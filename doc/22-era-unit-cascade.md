# 시대 선택 시 단원 자동 선택

완료일: 2026-09-05

## 배경

사용자: "지금은 시대나 단원이 가나다순으로 있긴 한데. 난 역사 지식이 그다지
좋지는 못한 편이거든? ... 시대에 맞게 단원이 자동으로 선택되게 하는 건
어떤지?"

`QuestionFilterPicker`의 시대·단원 체크박스가 서로 독립적이라, 어떤 단원이
어느 시대에 속하는지 교사가 직접 알아야 했다(예: "무신정변"이 고려시대
소속인지 몰라도 조선후기와 같이 체크할 수 있어 사용 가능한 문제가 0개가
되는 조합을 실수로 고를 수 있었음).

## 설계 결정

- **시대를 하나 이상 고르면, 단원 체크박스 목록 자체가 그 시대(들)에 실제
  존재하는 단원만으로 좁혀지고 전부 자동 체크된다.** 역사 지식 없이 시대만
  골라도 바로 사용 가능한 상태가 된다.
- **여러 시대를 고르면 각 시대 단원의 합집합**(중복 제거)을 보여준다 —
  단원 이름이 여러 시대에 걸쳐 재사용되는 경우(예: 교사가 "인물"을 삼국시대
  문제와 조선후기 문제 둘 다에 단원으로 붙인 경우)에도 정확히 한 번만
  나온다.
- **시대 선택이 바뀔 때마다 단원 선택을 그 시점 기준으로 다시 계산해서
  덮어쓴다** — "자동으로 선택되게"라는 요청 그대로, 시대를 만지면 단원도
  같이 재동기화된다. 그 뒤 개별 단원 체크박스를 손으로 더 좁히는 건 계속
  가능하다(다음에 시대를 또 바꾸기 전까지).
- **시대를 전부 해제하면 단원도 "제한 없음"으로 함께 풀린다**(빈 Set = 필터
  없음이라는 기존 규칙 그대로 — 특정 단원 목록을 억지로 다시 채워 넣지
  않는다. 그래야 나중에 새 단원이 추가돼도 "제한 없음" 상태가 자동으로
  포함한다).
- 난이도 필터는 이 자동화와 무관 — 그대로 독립적으로 동작한다.
- 7개 게임 설정 화면이 전부 `QuestionFilterPicker` 하나를 공유하므로, 이
  컴포넌트 안에서만 고치면 전체에 자동으로 적용된다 — 개별 Setup 파일은
  전혀 건드릴 필요가 없었다.

## 한 일

- `games/_shared/QuestionFilterPicker.tsx`: `unitsForEras(questions, eras)`
  헬퍼 추가(시대 미선택 시 전체 단원, 선택 시 해당 시대들의 단원 합집합).
  시대 체크박스의 `onChange`를 `handleEraToggle`로 교체 — 시대 Set을 토글한
  뒤 그 결과로 단원 목록을 다시 계산해 `filter.units`를 통째로 교체한다.
  단원 목록도 `unitsForEras`로 계산해 시대 선택에 따라 자동으로 좁혀지게
  했다. 시대가 하나 이상 선택됐을 때는 "단원(선택한 시대 안에서):" 라벨로
  현재 좁혀진 상태임을 알려준다.

## 검증 결과

- `unitsForEras`를 `tsx`로 직접 실행(임시 export 후 삭제): 시대 미선택 시
  전체 단원, 시대 하나 선택 시 그 시대 단원만, 여러 시대 선택 시 합집합,
  겹치는 단원 이름이 중복 없이 한 번만 나오는지 확인.
- `npm run typecheck` 통과.
- 브라우저로(fixture mock 디버그 하네스, 겹치는 단원 "인물"을 삼국시대·
  조선후기 양쪽에 배치해 검증) 확인: 시대 미선택 시 전체 5개 단원 → 삼국시대
  체크 시 3개 단원(고구려/백제/인물)으로 좁혀지고 전부 자동 체크(DOM
  `checked` 속성으로 직접 확인) → 조선후기까지 추가 체크 시 합집합 4개
  단원(고구려/백제/실학/인물)으로 확장, 문제 수 5개로 정확히 반영 → 시대를
  모두 해제하면 다시 전체 목록·전체 문제 수로 복귀. 문제 빙고 화면에서도
  기존 "난이도별 사용 가능한 문제 수" 안내와 함께 정상 동작 확인(다른 6개
  게임은 동일 공유 컴포넌트라 typecheck 통과로 갈음).
- 최종 `npm run dev`(Electron) 재부팅: 에러 없이 정상 기동 확인.
