# 5단계 계속: 땅따먹기

완료일: 2026-09-04

## 목표

CLAUDE.md 구현 순서: "땅따먹기 — SVG 역사 지도 위 지역 칸을 골라 문제 풀고 점령. 팀 대항.
추상 격자가 아니라 `data/maps/`의 실제 지도 SVG를 사용. 지도 교체로 단원 재사용."

실제 지도 SVG가 아직 없어 확인했고, **임시 지도로 시작**하기로 했다.

## 설계 결정

- **임시 지도**: `data/maps/samguk-placeholder.svg` — 삼국시대 관련 6개 지역(고구려/백제/
  신라/가야/동예/옥저)을 명백히 도식적인 배치(실제 지리와 무관)로 그렸다. "칸" 규격을
  `data-region-id`(필수)/`data-region-label`(표시용) 속성으로 정해서, 이 두 속성만 지키면
  어떤 SVG든 나중에 실제 지도로 교체해 쓸 수 있다.
- **지도는 런타임 데이터**: `data/questions.json`처럼 exe 옆 실제 파일에서 읽는다
  (`mapRepository` + `maps:*` IPC) — 지도 교체가 코드 수정 없이 파일 교체만으로 된다.
- **팀은 ClassManager 것을 그대로 사용**: 땅따먹기 설정 화면에 팀 관리 UI를 새로 안 만들고,
  학급에 이미 구성된 팀을 그대로 쓴다. 팀이 2개 미만이면 학급 관리에서 먼저 만들라고 안내.
- **턴제, 칸당 문제 하나, 결과 무관 턴 전환**: 라운드로빈으로 팀이 빈 칸을 고르면 무작위
  문제가 나오고, 정답이면 점령·오답이면 그대로 두고 다음 팀 차례. 이미 점령된 칸은
  재선택 불가, 판정 대기 중에는 다른 칸 선택 무시. 전 칸 점령 시 자동 종료(수동 "게임 종료"도 가능).
- **점수 = 점령 칸 수**: 타임어택의 콤보/난이도 배점 대신 칸 개수를 그대로 결과 점수로 씀.
- **문제 판정 UI는 새로 작성**: 타임어택 `HotSeatControls`와 로직이 비슷하지만, 이미
  검증되고 사용자 피드백으로 안정화된 코드를 건드리는 위험을 피하려고 별도로 작성했다.
  다만 순수 채점 로직(`gradeAnswer`)은 실제로 두 곳에서 똑같이 필요해서
  `games/_shared/gradeAnswer.ts`로 뽑아 타임어택도 같이 쓰도록 리팩터링했다.

## 발견하고 고친 버그: SVG 클릭이 두 번째 칸부터 안 먹힘

**증상**: 첫 번째 칸은 클릭이 되는데, 문제를 하나 풀고 나면 그다음부터는 어떤 칸을
클릭해도 반응이 없었다.

**원인**: `MapView`가 `dangerouslySetInnerHTML`로 넣은 SVG 내부 요소(지역 하나하나)에
직접 `addEventListener`로 클릭 리스너를 붙였는데, React가 리렌더링할 때 이 내부 DOM을
(문자열 내용이 같아도) 새 노드로 다시 만드는 경우가 있었다 — 실험으로 확인: 상태가
한 번 바뀌기 전/후로 같은 지역 요소를 가리키는 DOM 노드 객체가 서로 달라짐. 그러니 처음
붙인 리스너는 이제 화면에 없는 노드에 달려 있는 셈이 되어 이후 클릭이 씹혔다.

**수정**: 지역 요소 하나하나가 아니라, 그 바깥의 **컨테이너 `<div>`(React가 직접 관리하는
안정된 노드) 하나에만** 클릭 리스너를 위임으로 붙이고 `event.target.closest('[data-region-id]')`로
어느 칸이 클릭됐는지 판별하도록 바꿨다. 컨테이너 자체는 재생성되지 않으니 리스너가 계속
살아있다. 색칠 적용도 같은 이유로 "언제 재생성될지 모른다"고 보고 매 렌더마다 다시
적용하도록 했다.

**검증**: 이 버그는 리듀서 단위 테스트로는 못 잡는 종류라(DOM 상호작용 문제), Electron
없이 Vite 개발 서버를 브라우저로 띄워 실제 SVG를 클릭하며 찾았다. 수정 후 6개 칸을
전부 순서대로 클릭→판정→점령하는 전체 시나리오를 스크립트로 재현해 마지막 칸까지 전부
정상 처리되고 결과 화면으로 넘어가는 것까지 확인했다.

## 확인해 주세요

1. 학급 관리에서 팀이 2개 이상인 학급을 하나 준비(없으면 먼저 만들어야 함).
2. 홈 → 게임 시작 → 땅따먹기 → 그 학급 선택, 지도는 기본값(`samguk-placeholder.svg`) 그대로, 문제 필터 확인 → 시작.
3. 빈 칸 하나 클릭 → 문제가 뜨는지, 단답형이면 정답이 먼저 보이는지.
4. 정답 처리 → 그 칸이 해당 팀 색으로 칠해지고 옆 점수(칸 수)가 올라가는지, 차례가 다음 팀으로 넘어가는지.
5. 오답 처리 → 칸이 그대로 비어있고 차례만 넘어가는지.
6. 이미 점령된 칸을 다시 클릭해도 반응이 없는지.
7. 모든 칸을 다 점령할 때까지 진행 → 결과 화면(팀별 칸 수)이 뜨는지.
8. 중간에 "게임 종료"를 눌러도 그 시점 점수로 결과 화면이 뜨는지.

## 추가 개선: 지역별 문제 엄격 매칭 (2026-09-04)

사용자 지적: 지역이 고구려/백제/신라처럼 나라 이름이면, 고구려 칸에서 신라 문제가
나오는 건 이상하다 — 각 지역에 맞는 문제만 나오도록 분류가 필요함.

**확정된 동작(사용자 지시)**: "고구려로 태깅해둔 것만 고구려 문항에 나오도록" — 대체
없는 엄격한 매칭. 무관한 문제로 대체하지 않는다.

- 스키마 변경 없이 기존 `era`/`단원` 필드로 매칭한다: 지역 이름이 문항의 시대 또는
  단원에 포함되면(부분 문자열, 기존 필터들과 같은 방식) 그 지역 전용 문제로 인정.
  `games/territory/regionQuestionMatch.ts`.
- **트레이드오프**: 엄격하게 하기로 했으니, 어떤 지역에 태깅된 문제가 하나도 없으면
  그 지역은 점령이 아예 불가능해진다. 그래서:
  - `TerritorySetup`에 시작 전 지역별 매칭 문제 수를 미리 보여준다("고구려: 2개",
    "백제: 0개 ⚠"). 0개인 지역이 있어도 시작 자체는 막지 않는다(교사가 판단).
  - `TerritoryPlay`에서 태깅된 문제가 없는 지역을 클릭하면 판정으로 안 들어가고
    "이 지역에는 태깅된 문제가 없습니다" 안내만 뜬다.
- 기존에 있던 `TerritorySetup`의 시대/단원 텍스트 필터는 지역별 매칭이 그 역할을
  대신하므로 제거했다(전체 풀을 미리 좁히는 대신, 클릭 시점에 지역명으로 정확히 거른다).
- 리듀서 단위 테스트 9개 추가 검증(무관한 문제가 절대 안 나오는지, 태깅 없는 지역은
  선택 자체가 막히는지) + 브라우저에서 실제 클릭으로 최종 확인.
