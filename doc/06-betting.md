# 5단계 마지막: 베팅형

완료일: 2026-09-04

## 목표

CLAUDE.md 구현 순서 5단계 마지막: "베팅형 — 문제 공개 전에 보유 점수 일부를 배팅. 최종
문제 역전이 핵심." "향후 추가" 목록에서 "점수 베팅(더블 오어 나싱)"이 팀 대항형으로
분류돼 있어, 땅따먹기처럼 ClassManager의 팀을 그대로 쓰는 팀 대항 게임으로 만들었다.
이걸로 CLAUDE.md 5단계(타임어택 → 땅따먹기 → 베팅)가 전부 끝났다.

## 게임 진행 방식

- 팀마다 시작 점수(설정 화면에서 조정, 기본 1000)로 시작, 정해진 라운드 수(기본 5)만큼
  **배팅 → 문제 공개 → 팀별 판정 → 정산**을 반복한다.
- 배팅: 문제 공개 전 각 팀이 이번 라운드에 걸 점수를 입력(0~현재 점수, 더 못 검 — 이
  상한 덕분에 점수가 음수로 내려가는 일 자체가 구조적으로 없다).
- 판정: 문제가 뜨면(단답형은 정답을 먼저 보여줌) 팀마다 하나씩 그 팀이 말한 답을 입력.
- 정산: 정답이면 `+배팅액`, 오답이면 `-배팅액`(더블 오어 나싱). 전 팀 정산 후 결과를
  보여주고 다음 라운드로.
- 마지막 라운드는 "마지막 문제!"로 강조 표시.
- 문제는 게임 시작 시 셔플해서 라운드 순서대로 사용, 풀이 라운드 수보다 적으면 순환 —
  땅따먹기와 달리 여기선 반복이 문제 되지 않는다(라운드당 한 번만 정산되고 배팅액이
  라운드마다 새로 결정되므로, 같은 문제가 다시 나와도 추가 이득 구조가 아님).

## 한 일

  정산, 라운드 진행/종료), `BetInputRow`(배팅 입력), `TeamAnswerRow`(팀별 답 입력 —
  질문/정답 텍스트는 `BettingPlay`에서 한 번만 보여주고 이 컴포넌트는 입력 컨트롤만),
  `BettingSetup`(학급·라운드 수·시작 점수·문제 필터), `BettingPlay`(전체 화면 조립,
  라운드 결과·마지막 라운드 표시).
- 채점은 기존 `games/_shared/gradeAnswer.ts` 재사용.
- `GameSelect.tsx`에 "베팅형" 추가.

## 검증 결과

- `npm run typecheck` 통과.
- **리듀서 로직**: `tsx`로 직접 실행해 15개 항목 검증 — 배팅 상한(초과 배팅 시 최대치로
  잘림, 음수는 0으로), 정답/오답 정산 금액, 라운드 전환, 라운드 수 소진 시 종료, 종료 후 no-op.
- **화면 흐름**: Electron 없이 브라우저로 실제 클릭 재현 — 배팅 입력→문제 공개→팀별
  판정→정산→다음 라운드(마지막 라운드 표시 포함)→종료까지 전부 확인. 1라운드는
  독수리팀 정답(+300)/호랑이팀 오답(-500)으로, 2라운드(마지막)는 두 팀 다 올인해서
  호랑이팀이 역전하는 시나리오까지 재현.

## 확인해 주세요

1. 학급 관리에서 팀이 2개 이상인 학급 준비.
2. 홈 → 게임 시작 → 베팅형 → 학급 선택, 라운드 수/시작 점수 확인 → 시작.
3. 팀별로 배팅액 입력(보유 점수보다 많이 넣으면 자동으로 최대치로 잡히는지) → 문제 공개.
4. 문제 화면에서 단답형이면 정답이 먼저 보이는지, 팀마다 하나씩 판정 → 전 팀 판정 전엔 "정산하기"가 비활성인지.
5. 정산 후 배팅액만큼 점수가 오르내리는지, 다음 라운드로 넘어가면서 배팅 입력이 0으로 초기화되는지.
6. 마지막 라운드에서 "마지막 문제!" 표시가 뜨는지, 끝나면 결과 화면(팀 최종 점수)이 뜨는지.
7. 중간에 "게임 종료"로 수동 종료해도 그 시점 점수로 결과가 뜨는지.
