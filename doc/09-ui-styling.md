# UI 스타일링 — 게임 화면(프로젝터용) + 관리 화면(데스크탑용)

완료일: 2026-09-04

## 목표

CLAUDE.md 구현 순서 1~6단계와 포터블 exe 재검증이 끝난 뒤, "기능부터 다 끝내고
스타일은 나중에 한 번에" 방침대로 미뤄뒀던 UI 스타일링을 진행. CLAUDE.md 유의사항
"교실에서 TV 또는 프로젝터로 띄운다. 글자와 버튼을 크게, 뒷자리에서 읽히도록."를
실제로 반영하는 단계.

사용자 확인 사항(작업 전 질문으로 확정):
- 게임 진행 화면(프로젝터로 띄우는 부분)만 아주 크게, 관리 화면(표·폼이 많은 화면)은
  데스크탑에서 보기 편한 보통 크기로 — 두 화면군을 다르게 스타일링.
- 글자 크기 실시간 조절 기능은 넣지 않음. CSS로 넉넉한 고정 크기만.

## 설계

- **전역 CSS 파일 신설**: [src/renderer/src/styles/global.css](../src/renderer/src/styles/global.css),
  `main.tsx`에서 한 줄로 import(Vite 기본 지원, 빌드 설정 변경 없음).
  - `:root`에 디자인 토큰(CSS 커스텀 프로퍼티): 색상 2세트(관리 화면 밝은 배경 vs
    게임 화면 어두운 배경), 간격 스케일, 시스템 한글 폰트 스택(`'Malgun Gothic',
    'Apple SD Gothic Neo', sans-serif` — 폰트 파일 번들 안 함, CSP 변경 불필요).
  - 베이스 리셋으로 `button`/`input`/`table` 등 raw 요소 기본값을 관리 화면 수준으로.
  - 관리용 유틸리티 클래스: `.page`, `.button-primary`/`.button-danger`, `.data-table`,
    `.field-row`, `.button-row`, `.panel` 등 — 여러 파일에 중복돼 있던 인라인 style
    상수(`cellStyle` 등)를 이 클래스들로 대체.
  - 게임용 `.stage` 계열: `.stage`(어두운 배경 컨테이너), `.stage-title`,
    `.stage-timer`(초대형), `.stage-question`(대형), `.stage-button`, `.stage-panel`,
    `.stage-scoreboard`, `.stage-answer-reveal`(정답/오답 배너), `.stage-map-frame`
    (땅따먹기 지도 테두리).
  - 팀 색상처럼 런타임 계산값(`teamColors[team.id]` 등)은 계속 인라인 `style`로 유지.
- **적용 범위**: 렌더러 컴포넌트 전체(약 24개 파일) — 컨테이너의 인라인
  `style={{padding:'2rem',...}}`를 `className="page"`(관리) 또는 `className="stage"`
  (게임)로 교체. 게임 화면: `TimeAttackPlay`/`TerritoryPlay`/`BettingPlay`와 이들이
  쓰는 `Scoreboard`/`AnswerReveal`/`HotSeatControls`/`SimultaneousControls`/
  `QuestionJudgePrompt`/`TeamAnswerRow`/`BetInputRow`, 게임 직후 `Result`. 관리 화면:
  `Home`/`QuestionBank`(+`QuestionForm`/`CsvImportPanel`)/`ClassManager`(+`ClassRoster`/
  `TeamManager`/`RosterPasteImport`)/`GameSelect` 선택 화면/세 `*Setup`/`SessionHistory`.
  로직·prop 시그니처는 건드리지 않은 순수 스타일 작업.
- **창 기본 크기 확대**: [src/main/index.ts](../src/main/index.ts)의 `createWindow()` —
  `1000x700` → `1280x800`으로, 프로젝터 연결 시 처음부터 더 넓게 시작하도록.

## 검증 결과

- `npm run typecheck` 통과(스타일 작업만이라 컴포넌트 시그니처 변화 없음, 리스크 낮음).
- **브라우저 실검증**: `main.tsx`를 임시로 `window.questions`/`window.classes`/
  `window.maps`/`window.sessions`를 fixture로 mock한 뒤 실제 `<App/>`을 그대로
  렌더링하는 디버그 하네스로 교체(Electron IPC 없이 실제 라우팅/화면 전환을 그대로
  타는 방식 — 이전 단계들의 "게임 컴포넌트 직접 렌더" 방식보다 한 단계 더 실제
  흐름에 가까움), 확인 후 원복:
  - 관리 화면(문제은행 표, 학급관리 로스터 표)이 밝은 배경에 정돈된 표/버튼으로 보임.
  - 타임어택 진행 화면: 어두운 배경에 초대형 타이머·문제 텍스트·큰 답안 버튼,
    정답/오답 배너(초록/빨강)가 뚜렷한 대비로 표시됨, 점수판 "수정" 인라인 편집도
    어두운 테마에서 정상 동작.
  - 땅따먹기: SVG 지도가 `.stage-map-frame`으로 테두리가 잡혀 어두운 배경 위에서도
    도드라져 보임, 지역 선택→판정→점령 후 "지역 재배정" 패널까지 전부 어두운
    테마로 일관되게 표시됨.
  - 베팅형: 배팅 입력 행, 팀별 답 판정 패널이 스테이지 스타일로 정상 표시됨.
  - `SessionHistory`(관리 화면)도 세션 목록/오답 통계 표가 정돈되어 보임.
  - 확인 후 `main.tsx` 원복, 개발 서버·잔여 electron/node 프로세스 정리.
- **최종 부팅 확인**: 정리 후 실제 `npm run dev`(Electron)로 재부팅 — 에러 없이
  main/preload 빌드 성공, `paths` 로그 정상, 임시 코드 흔적 없음 확인.

## 확인해 주세요

1. `npm run dev`로 실제 앱을 띄워 홈 → 문제은행/학급관리(보통 크기)와
   게임 시작 → 아무 모드나 플레이(큰 글자/버튼)의 느낌 차이를 직접 확인.
2. 가능하면 실제 TV나 프로젝터에 연결해 뒷자리에서 문제 텍스트·타이머·버튼이
   읽히는지 확인 — 이번 작업은 화면 크기 400px 안팎의 브라우저 창에서 검증했기
   때문에, 실제 대형 화면에서의 체감은 다를 수 있음.
3. 창을 최대화했을 때 게임 화면 레이아웃(가운데 정렬, 최대 너비)이 넓은 화면에서도
   괜찮아 보이는지.

## 색상 팔레트 수정 (2026-09-04, 사용자 피드백 반영)

1차 작업 때는 색상을 사용자에게 확인하지 않고 임의로 정해(관리 화면 밝은 회백색 +
게임 화면 짙은 남색 다크테마) 진행했다가, "색상은 상아색으로 할 거라고 말하려던
참이었는데 왜 마음대로 정했냐", "버튼이 브라우저 기본 디자인처럼 대충 보인다"는
피드백을 받았다. 구조/범위(게임 화면 vs 관리 화면 크기 차등, 고정 크기 등)는
사전에 확인받았지만, 색상·완성도 같은 취향의 영역은 별도로 여쭤봤어야 했다는
점을 놓쳤다 — 이 교훈은 메모리에 별도로 기록해뒀다.

사용자가 준 방향("배경색은 상아색, 역사 하면 떠오르는 톤")에 따라 팔레트를
다시 잡았다. **관리 화면과 게임 화면 모두 같은 상아색(고서·한지 느낌) 계열로
통일**하고, 게임 화면은 톤을 살짝 더 짙게(`--stage-bg` #e9d4a0 vs 관리 화면
`--color-bg` #f2e6c9)만 줘서 "지금은 게임 중"이라는 구분만 남겼다 — 이전의
밝음/어두움 이분 대신, 하나의 역사 테마 안에서 톤 차이로 구분하는 방식으로 바꿨다.

- 배경(관리): `#f2e6c9`(상아/파피루스), 카드·입력창: `#fbf4e2`
- 배경(게임 화면): `#e9d4a0`(살짝 더 짙은 톤), 카드: `#f8efd9`
- 글자: `#3a2b1a`(먹빛에 가까운 짙은 갈색, 두 화면 공통)
- 포인트 색(주요 버튼): `#2c4a6e`(청화백자 남색 계열) — 정답/오답에 쓰는
  초록(`#4b7a3f`)·빨강(`#a1392a`)과 겹치지 않도록 파란 계열로 선택
- 위험/삭제 버튼과 오답 배너: `#a1392a`(낙관 도장을 연상하는 벽돌색 빨강)
- 정답 배너: `#4b7a3f`(차분한 녹색)
- 테두리: `#c7ac78`(관리)/`#ad8c54`(게임, 더 굵고 진하게)

**버튼/카드 완성도**도 같이 손봤다 — 이전엔 테두리만 두른 브라우저 기본 버튼이었던
것을, `font-weight:600` + 은은한 그림자(`box-shadow`) + 클릭 시 눌리는 느낌
(`transform: translateY(1px)`)을 추가해 더 만든 티가 나게 했다. 표(`panel`,
`data-table`, `stage-panel`)에도 옅은 그림자를 줘서 배경과 살짝 분리돼 보이게 했다.

**표 줄바꿈 버그도 같이 고쳤다**: 좁은 열(난이도/유형처럼 글자 수 적은 열)이
글자 크기가 커지면서 한 화면 안에 다 들어가려다 한글이 음절 단위로 줄바꿈되는
문제였다 — 표의 `th`/`td` 기본값을 `white-space: nowrap`으로 바꾸고, 실제로 길어서
줄바꿈이 필요한 셀(질문 내용, 오답 통계의 질문, CSV 미리보기 내용 등)에만
`.wrap-text` 클래스를 따로 붙였다. 혹시 그래도 표가 화면보다 넓어지는 경우에
대비해 표를 `.table-scroll`(가로 스크롤 컨테이너)로 감쌌다.

**팀 색상은 그대로 유지**했다: 땅따먹기 지도·점수판에서 모둠을 구분하는
파랑/빨강/초록/노랑/보라/청록(`mapSvg.ts`의 `TEAM_COLORS`)은 상아색 배경 위에서도
또렷이 구분돼야 하는 기능적 색이라 "배경색을 상아색으로"라는 요청 범위 밖으로
보고 손대지 않았다. 필요하면 알려주시면 톤을 맞추겠다.

검증은 동일한 디버그 하네스 방식(실제 `<App/>`을 IPC만 mock해서 그대로 렌더링)으로
다시 진행 — 문제은행 표(줄바꿈 정상화 확인), 홈/게임 선택/타임어택 설정·진행
화면(상아색 배경 + 남색 포인트 버튼 + 정답 배너 색 대비)까지 스크린샷으로 확인.
