# 학급 관리 화면 CSS 전면 개편

완료일: 2026-09-05

## 목표

게임 모드 10개를 다 만든 뒤 미뤄뒀던 CSS 작업의 첫 대상. 사용자 요청:
"학급 관리의 CSS를 전면 수정. 버튼 크기, 버튼 애니메이션 등 너의 최대치를
발휘하여 맛깔나게 디자인해봐. 불릿 같은 거 쓰지 말고."

## 배경 — 이번엔 색상 방향을 다시 묻지 않은 이유

세션 초반에 "시각 디자인은 방향을 먼저 물어야 한다"는 피드백을 받은 적이
있지만(`feedback_visual_design_needs_explicit_direction` 메모리), 그건
**아직 팔레트가 없던 시점**의 이야기다. 이미 홈 화면·게임 선택 화면에서
상아색/한지 팔레트(`--color-*`, `--home-*`, `.mode-*` 등)로 두 번
"맛깔나게" 리디자인을 했고 둘 다 승인받았다 — 이번엔 그 확립된 언어를
학급 관리 화면까지 확장하는 것이므로, 새로 색상 방향을 묻지 않고 기존
팔레트·애니메이션 패턴(`home-fade-in-up`, hover lift, 아이콘 SVG 스타일)을
그대로 재사용했다.

## 설계 결정

- **관리 화면(밝은 상아색) 카테고리를 유지했다** — 학급 관리는 교사가
  데스크탑에서 쓰는 화면이지 프로젝터로 띄우는 게임 화면이 아니므로,
  어두운 `.stage` 계열이 아니라 기존 `.page`/`.panel` 계열의 확장으로
  디자인했다.
- **`<ul>`/`<li>` 3곳을 전부 없앴다**(사용자가 명시적으로 요청):
  - `ClassManager.tsx`의 학급 목록 → 카드 그리드(`.class-grid`/`.class-card`).
  - `TeamManager.tsx`의 팀 목록 → 알약형 카드(`.team-grid`/`.team-card`).
  - `RosterPasteImport.tsx`의 미리보기 목록 → 알약형 칩(`.roster-preview`).
- **학급 카드는 카드 전체가 클릭 대상**(진입)이고, 그 안의 "삭제" 버튼은
  `event.stopPropagation()`으로 분리했다. `<button>` 안에 `<button>`을
  중첩할 수 없어서 카드 자체는 `role="button" tabIndex={0}` div로,
  삭제만 실제 `<button>`으로 만들어 키보드 접근성과 HTML 유효성을 함께
  지켰다.
- **삭제 버튼은 평소엔 흐리게, 카드에 마우스를 올렸을 때만 또렷해진다**
  (`opacity: 0` → hover 시 `1`) — 목록을 훑어볼 땐 이름만 눈에 들어오고,
  실제로 지우려 할 때만 버튼이 나타나는 편이 실수 클릭을 줄인다고 판단.
- **아이콘은 이모지·기호 문자 없이 인라인 SVG**로 통일 — 게임 선택 화면
  때 정한 방침을 그대로 이어받아 `pages/ClassManager/icons.tsx`에
  `PeopleIcon`/`PlusIcon`/`TrashIcon`/`ShuffleIcon`/`PasteIcon`을 모아뒀다
  (여러 파일에서 재사용되는 첫 아이콘 세트라 공유 파일로 분리 — 지금까지는
  파일마다 로컬로 아이콘을 정의해왔지만, 이번엔 4개 파일이 같은 아이콘을
  공유해서 처음으로 별도 파일을 뺐다).
- **버튼 크기**: 핵심 액션(학급 추가·학생 추가·팀 추가)에 새 `.button-lg`
  유틸리티 클래스를 얹어 눈에 띄게 키웠다. 이 클래스는 전역 `button`
  기본 스타일은 건드리지 않고 학급 관리에서만 opt-in으로 쓴다 — 다른
  화면의 버튼 크기에 영향 없음.
- **기존 `.icon-button` 클래스**(게임 선택 화면의 "← 홈" 버튼에서 이미
  쓰던 아이콘+텍스트 정렬용)를 새 버튼들에도 그대로 재사용해 아이콘과
  글자가 수직으로 잘 맞게 했다.
- **표는 그대로 뒀다**(학생 명단, 학생-팀 배정) — 번호/이름/소속팀처럼
  열이 있는 구조화된 목록은 표가 카드보다 스캔하기 쉽고, 애초에 표는
  "불릿"이 아니라서 사용자 요청 범위 밖이라고 판단. 대신 행에 마우스를
  올리면 배경이 옅게 강조되는 `.roster-table` hover 효과만 추가했다.
- **섹션 제목에 아이콘 + 개수 배지**를 붙이는 `.section-header` 패턴을
  새로 만들어 "학생 명단 4명", "팀 구성 2개 팀"처럼 통일된 형태로 보이게
  했다.

## 한 일

- `pages/ClassManager/icons.tsx`(신규) — 공유 아이콘 5종.
- `styles/global.css` — "학급 관리" 섹션 신설: `.button-lg`,
  `.class-toolbar`, `.class-empty`, `.class-grid`/`.class-card`(+아이콘/
  이름/인원 배지/삭제 버튼 하위 클래스), `.section-header`/`.section-count`,
  `.roster-table`(hover), `.team-grid`/`.team-card`(+이름/인원/삭제 버튼),
  `.roster-preview`/`.roster-preview-pill`. 기존 `home-fade-in-up`
  키프레임을 그대로 재사용해 카드마다 순차 등장 애니메이션을 줬다.
- `ClassManager.tsx` — 학급 목록을 카드 그리드로, 빈 상태 안내 문구 추가,
  "학급 추가" 버튼 확대.
- `ClassRoster.tsx` — 섹션 헤더 도입, "학생 추가"/"명단 붙여넣기"/"삭제"
  버튼에 아이콘 부착 및 확대.
- `TeamManager.tsx` — 팀 목록을 알약형 카드로, 섹션 헤더 도입, "팀 추가"/
  "자동 나누기" 버튼에 아이콘 부착.
- `RosterPasteImport.tsx` — 미리보기 목록을 알약형 칩으로 교체.

## 검증 결과

- `npm run typecheck` 통과.
- 브라우저로(fixture mock 디버그 하네스) 실제 확인: 학급 카드 그리드가
  불릿 없이 렌더링되는지, 카드 호버 시 리프트+그림자+삭제 버튼 등장
  애니메이션이 실제로 동작하는지(`hover` 액션 후 스크린샷으로 확인),
  카드 클릭 시 학생/팀 관리 화면으로 정상 진입하는지, 학생 명단 섹션
  헤더·아이콘·개수 배지가 정상 표시되는지, 명단 붙여넣기로 학생을 추가하면
  실제로 목록에 반영되는지("4명"→"7명"), 팀 목록이 알약형 카드로 표시되는지,
  명단 붙여넣기 미리보기가 칩 형태로(번호 강조 포함) 표시되는지. 콘솔
  에러 없음.
- 최종 `npm run dev`(Electron) 재부팅: 에러 없이 정상 기동 확인.
