# 보스 레이드(협동형)

완료일: 2026-09-04

## 목표

랭킹 3순위. "반 전체가 HP를 가진 보스를 상대. 정답이 곧 데미지. 경쟁 대신 협력이
필요한 반에 유용."(CLAUDE.md)

작업 시작 전 사용자가 "나중에 학생 개인 기기 답안이 교사 기기와 연동돼야 할
텐데"를 짚었다 — 이건 CLAUDE.md 참여 방식 규칙(게임 로직은 정규화된
`Answer{participantId, value, submittedAt}` 객체만 소비하고, 응답이 교사
키보드에서 왔는지 나중에 학생 기기에서 왔는지 몰라야 한다)이 이미 대비해둔
지점이다. 지금까지 만든 모든 게임이 이 규칙을 지키고 있고(특히 "Answer 타입
통일" 작업으로 명시적으로 맞춰둠), 보스 레이드도 같은 방식으로 만들었다 — 실제
학생 기기 연동(네트워크 레이어 등)은 CLAUDE.md가 명시적으로 v1 범위 밖으로
못박아둔 별개의 큰 작업이라 이번에 만들지 않았다.

## 설계 결정

- **참가자는 개인 학생 목록**(땅따먹기/베팅형의 팀 모델이 아니라 타임어택처럼
  `selectedClass.students`) — 반 전체가 "하나의 팀"으로 보스와 싸우는 구도라서.
- **턴이 없다** — 타임어택 "동시 진행" 모드와 같은 구조. 아무 학생이나 답할 수
  있고 교사가 검색해서 골라 판정한다. 객관식·단답형 둘 다 지원(데미지 계산이
  문항 유형과 무관해서 좁힐 이유가 없었음).
- **데미지 = 기존 타임어택 점수 공식 재사용**
  (`calculateScoreForCorrectAnswer(difficulty, combo)`를 "피해량"으로).
- **콤보는 개인별이 아니라 학급 전체가 공유** — 서로 다른 학생이 번갈아 맞혀도
  계속 쌓인다. 협동이라는 취지를 데미지 공식에 직접 반영.
- **오답 페널티 없음** — 협동 게임에서 개인에게 불이익을 주면 취지에 안 맞는다.
  콤보만 끊고 문제는 유지해 다른 학생이 재시도할 수 있게 한다.
- **개인 점수 = 기여한 데미지 합** — 경쟁용이 아니라 "누가 얼마나 기여했는지"
  기록용. `Scoreboard`/세션 기록 파이프라인이 `ParticipantScore[]`를 요구해서
  자연스럽게 필요하기도 하다.
- **교사 수동 개입 = 보스 체력 직접 조정** — 땅따먹기의 "지역 재배정"과 같은
  이유로, 게임의 진짜 상태(개인 점수가 아니라 보스 체력)를 직접 고칠 수 있게
  했다.
- **보스 체력 게이지는 이미지 없이 CSS 바로 표현.** Setup에서 보스 이름(기본값
  있는 텍스트)과 보스 체력(선택한 문제 수 × 30을 기본 제안, 교사가 직접 입력하면
  더는 자동으로 안 따라감)을 받는다.
- 엔진은 새로 작성(힌트 차감형과 같은 이유 — 공유 체력·공유 콤보라는 새 상태
  모델이 필요해 기존 엔진에 얹지 않음). 단답형 판정에는 지난번 만든
  `AnswerConfirm`을 그대로 적용해 정답 텍스트를 기본적으로 숨겼다.

## 검증 결과

- `npm run typecheck` 통과.
- 리듀서를 `tsx`로 직접 실행해 22개 항목 검증: 오답 시 체력·문제 유지·콤보만
  리셋·개인 페널티 없음, 정답 시 데미지가 공유 콤보에 따라 커짐(다른 학생이
  이어 맞혀도 콤보 누적), 체력이 음수로 안 내려가고 0이 되면 즉시 종료, 문제
  큐 소진 시에도 종료(보스 생존 가능), `ADJUST_BOSS_HP`가 0~최대치로 클램프되며
  정확히 반영, `END_GAME_MANUALLY` 즉시 종료.
- 브라우저로(fixture mock 디버그 하네스) 실제 플레이: Setup에서 문제 수×30 기본
  체력 제안 확인, 정답 시 체력 게이지·콤보 증가 확인(난이도1×콤보1=10 데미지로
  90→80 정확히 감소), 단답형 문제에서 정답 텍스트가 기본적으로 숨겨지는 것 확인,
  보스 체력 수동 조정(90→50) 반영 확인, 게임 종료 후 결과 화면과 세션 기록에
  "보스 레이드"로 정확히 저장되는 것 확인.
- 최종 `npm run dev`(Electron)로 재부팅 확인.
