# 3단계: 학급/학생·팀 관리

완료일: 2026-09-04

## 목표

CLAUDE.md 구현 순서 3단계. 게임을 시작하기 전에 이 반 학생이 누구고 팀은 어떻게
나뉘는지가 준비돼 있어야 한다. CLAUDE.md에는 이 단계의 구체적 스키마가 없어서
(문항 스키마와 달리 예시조차 없었음) 이번 단계에서 새로 설계했다.

## 설계 결정

- **학생 명단도 붙여넣기 지원**: 2단계의 "CSV 붙여넣기 최우선" 원칙이 학생 명단에도
  그대로 적용된다고 보고, 헤더 없이 "번호,이름" 또는 이름만 한 줄씩 붙여넣는 방식을
  추가했다 ([schoolClassRoster.ts](../src/shared/schoolClassRoster.ts)).
- **팀은 학급에 저장하되 언제든 수정 가능**: "미리 짜두기"와 "매번 새로 구성" 둘 다를
  강제로 양자택일하지 않고, 학급 데이터 안에 저장하되 화면에서 자유롭게 다시 배정할
  수 있게 했다.
- **자동 팀 나누기**: N을 입력하면 학생을 무작위로 섞어 균등 분배하는 버튼을 추가했다.
  수동 배정만 있으면 팀을 자주 섞는 게임에서 매번 번거로워진다.

## 한 일

- **스키마** ([schoolClass.ts](../src/shared/types/schoolClass.ts)): `SchoolClass { id, name, students, teams }`.
  `isSchoolClassDraft` 검증에 문항의 `answerIndex` 범위 검증과 같은 수준으로
  **팀의 studentIds가 실제 학급 학생 목록에 존재하는지(참조 무결성)**까지 확인하도록 했다.
- **데이터/IPC**: [classRepository.ts](../src/db/repositories/classRepository.ts)
  (`getAll/create/update/remove`, `jsonFile.ts` 재사용 — 2단계에서 의도했던 재사용이
  실제로 일어남), `src/main/ipc/classes.ts`, preload의 `window.classes.*`.
  학생 추가/삭제/팀 배정은 별도 IPC 없이 렌더러가 학급 객체를 통째로 수정해 `update`로
  저장하는 방식 — 이미 메모리에 로드된 객체라 별도 bulk 엔드포인트가 필요 없었다.
- **화면**: `pages/ClassManager/` — 학급 목록/추가/삭제, 학생 명단(개별 추가+붙여넣기),
  팀 구성(추가/삭제/드롭다운 배정/자동 나누기)을 파일별로 분리.
  Home 화면에 "학급 관리" 버튼 추가.

## 검증 결과

- `npm run typecheck` 통과.
- **자동 검증(직접 수행)**: 2단계와 같은 방식으로 메인 프로세스에 임시 자가진단 코드를
  넣어 `npm run dev`로 실행 → 학급 생성, 학생 추가, 팀 배정, **참조 무결성 위반 데이터
  정상 거부**("올바르지 않은 학급 데이터입니다."), 삭제까지 로그로 전부 확인. 검증 후
  임시 코드 제거, `data/classes.json`은 빈 배열 상태.
- **화면 조작(사람 확인 필요)**: 아래 참고.

## 확인해 주세요

`npm run dev`로 실행한 뒤:
1. 홈 → "학급 관리" → 학급 추가(예: "1학년 3반").
2. 학생 몇 명 개별 추가 + "명단 붙여넣기"로 `1,김민준` / `2,이서연` / `박도윤`처럼
   번호 있는 줄과 없는 줄을 섞어서 붙여넣기 → 둘 다 정상 추가되는지.
3. 팀 추가 후 학생별 드롭다운으로 소속팀 배정 → 명단 테이블의 "소속팀" 칸에 반영되는지.
4. "N팀으로 자동 나누기" → 기존 배정이 대체되고 인원이 고르게 나뉘는지.
5. 학급 삭제 → 목록에서 사라지는지.
