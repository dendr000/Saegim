# 4단계 + 5단계 일부: games/_shared 공통 엔진 + 타임어택 콤보

완료일: 2026-09-04

## 목표

CLAUDE.md 구현 순서 4단계("games/_shared 공통 엔진: 타이머, 점수판, 정답 연출, 입력 계층")를
5단계 첫 게임(타임어택 콤보)과 함께 진행했다. 실제 게임 없이 엔진만 먼저 설계하면 막상
게임을 만들 때 안 맞을 위험이 있어서, 가장 단순한 게임 하나를 같이 만들며 거기서 실제로
필요한 형태로 공통 부분을 뽑아냈다 (자세한 배경은 계획 승인 시점 대화 참고).

## 설계 결정

- **타임어택 진행 방식 2가지, 게임 시작 전 선택**: 사용자에게 "학생 개인 기기가 없는
  상태에서 어떻게 진행하고 싶은가" 물었고, 핫시트(한 명씩 순서대로)와 동시 진행(전체,
  손 든 사람이 점수) 둘 다 지원하고 시작 전에 교사가 고르는 방식으로 확정했다.
  - 핫시트: 오답이어도 바로 다음 문제로 (같은 문제 재시도 없음). 시간 만료 시 다음 학생.
  - 동시 진행: 오답이면 그 학생 콤보만 끊기고 문제는 유지(다른 학생이 계속 시도 가능),
    "다음 문제"로 스킵 가능. 정답이 나오면 자동으로 다음 문제.
- **입력 계층은 "판정"이 아니라 "학생이 말한 답"을 전달**: CLAUDE.md 규칙 3(게임 로직은
  응답 출처를 몰라야 함)을 지키기 위해, 교사 클릭이 직접 정답/오답 여부가 아니라
  `Answer.value`(객관식은 `{choiceIndex}`, 단답형은 음성 채점이 불안정해 `{judgedCorrect}`)를
  만들고 엔진이 문제 데이터와 대조해서 정오를 계산한다.
- **효과음은 합성음**: 실제 음원 파일 없이 Web Audio API로 짧은 비프음을 생성. 라이선스
  걱정 없고 에셋 준비도 불필요.
- **점수 공식**: `난이도 × 10 × 콤보단계`. `games/timeAttack/scoring.ts` 한 곳에 몰아둬서
  나중에 실제 플레이해보고 조정 가능.

  `scoring.ts`, `TimeAttackSetup`(학급/참가자/모드/시간/문제필터), `TimeAttackPlay`,

## 검증 결과

- `npm run typecheck` 통과.
- **리듀서 로직 직접 실행 검증**: `useTimeAttackEngine`의 리듀서는 UI/Electron 없이 순수
  함수라 `tsx`로 실제 코드를 직접 불러와 20개 항목을 검증했다 — 핫시트 턴 전환, 동시 진행
  모드에서 오답 시 문제 유지/정답 시 진행, 콤보 초기화, 종료 후 no-op, 그리고 콤보 공식
  (난이도 2 문제 3연속 정답 → 20/40/60점, 공식과 정확히 일치)까지 확인. 셔플이 랜덤이라
  같은 테스트를 5회 더 반복 실행해 우연이 아님을 확인. 검증 후 테스트용 임시 export와
  스크립트는 제거함.

## 확인해 주세요

이번 단계는 지금까지 중 가장 복잡한 화면이라 꼭 두 모드 다 한 번씩 진행해봐 주셨으면 한다.

**핫시트 모드**
1. 홈 → "게임 시작" → "타임어택 콤보" → 학급 선택, 참가 학생 선택, "핫시트" 선택, 제한시간 설정 → 시작.
2. 문제가 뜨면 첫 번째 학생 차례로 표시되는지, 객관식은 보기 버튼이 단답형은 정답/오답 버튼이 뜨는지.
3. 정답을 몇 번 연속으로 눌러서 콤보가 올라갈수록 점수가 더 많이 붙는지, 오답을 누르면 바로 다음 문제로 넘어가면서 그 학생 콤보만 끊기는지.
4. 제한시간이 다 되면 다음 학생 차례로 자동으로 넘어가는지 (타이머도 그 학생 걸로 새로 시작하는지).
5. 마지막 학생까지 끝나면 결과 화면(순위표)이 뜨는지.

**동시 진행 모드**
1. 다시 시작해서 이번엔 "동시 진행" 선택.
2. 문제가 뜨면 "답한 학생" 선택 드롭다운이 있는지, 학생을 고르고 오답을 누르면 문제가 안 바뀌고 그 학생 콤보만 끊기는지.
3. 다른 학생을 고르고 정답을 누르면 다음 문제로 자동으로 넘어가는지.
4. "다음 문제(스킵)"를 눌러도 정상적으로 다음 문제로 넘어가는지.
5. 전체 제한시간이 다 되면 결과 화면으로 넘어가는지.

**공통**
- 정답/오답 시 소리가 나는지 (합성음이라 단순한 삐- 소리).
- 정답 공개 배너(초록/빨강)가 제대로 뜨는지.

## 사용자 테스트 후 수정 (2026-09-04)

실제로 플레이해보고 나온 피드백 세 가지를 반영했다.

1. **단답형 판정 버튼에 정답이 안 보였음** — "정답/오답 버튼이 왜 있는지 모르겠다"는
   피드백의 원인은 버그였다. 교사가 판정하려면 정답이 뭔지 알아야 하는데 화면에
   안 떠 있었다. `HotSeatControls`/`SimultaneousControls`에 판정 버튼 위에
   "정답: X (Y도 정답)"을 먼저 보여주도록 고쳤고, 버튼도 "정답 처리"/"오답 처리"로
   명확히 했다.
   
2. **핫시트: 문제 풀을 다 풀면 반복 출제되며 점수 파밍이 가능했음** — 문제가 2개뿐인데
   60초를 주면, 10초 만에 다 풀고 남은 50초 동안 같은(이미 정답을 아는) 문제가
   반복 출제되어 무한히 점수를 쌓을 수 있었다. `useTimeAttackEngine`의 문제 진행
   방식을 "매번 전체 풀에서 순환"에서 **"이번 범위(핫시트는 이 학생의 턴, 동시 진행은
   세션 전체)의 문제를 다 냈으면 반복하지 않고 그 범위를 끝낸다"**로 바꿨다. 핫시트는
   다음 학생으로, 동시 진행은 세션 종료로 넘어간다. 추가로 교사가 언제든 수동으로
   턴/세션을 끝낼 수 있는 버튼도 넣었다 — 핫시트엔 "다음 학생으로 →", 동시 진행엔
   "게임 종료". 둘 다 리듀서 로직을 직접 실행해서(순수 함수 단위 테스트) 반복 방지와
   수동 종료가 정확히 동작함을 확인했고, 브라우저에서 실제 클릭까지 재현해서 검증함.

3. **동시 진행: 학생이 많을 때 드롭다운이 불편함** — 20명 넘는 실제 학급을 고려해
   `SimultaneousControls`의 참가자 선택을 드롭다운에서 **이름 텍스트 검색**으로
   바꿨다. 타이핑하면 일치하는 학생만 걸러져 보이고 클릭하면 선택되며, 문제가
   바뀌면 선택이 자동으로 초기화된다.

이 세 가지는 모두 `npm run dev`를 직접 켤 필요 없이, Electron 없이 Vite 개발 서버만
브라우저로 띄워 실제 컴포넌트를 구동해 검증했다 — 앞으로 화면 동작을 확인할 때도
이 방법을 쓸 수 있다(단, `window.classes`/`window.questions` 같은 IPC API가 필요 없는
화면에 한해서).
