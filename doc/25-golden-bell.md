# 골든벨 서바이벌 (개인전 · 전체 참여형)

완료일: 2026-09-05

## 목표

[23-remaining-game-modes-plan.md](23-remaining-game-modes-plan.md)에서 정한
7순위 게임. CLAUDE.md: "골든벨 서바이벌 — 틀리면 탈락, 단 부활 문제 1회.
탈락자는 심판이나 응원단 역할을 주면 이탈 방지." 매 라운드 생존자 전원이
동시에 같은 문제에 답하고 교사가 전원을 한 화면에서 판정해야 하는, 지금까지
없던 "전원 체크리스트" UI가 필요한 첫 게임.

## 설계 결정 — 부활권 (계획 단계에서 재확인 후 변경)

당초 계획 문서([23번](23-remaining-game-modes-plan.md))에는 "전원에게 자동으로
부활권 1개씩"을 제안했으나, 착수 전 확인 과정에서 사용자가 정정: **부활권은
자동 지급이 아니라 교사가 전적으로 통제한다.**

- 시작 전 Setup 화면에서 특정 참가자에게만 선택적으로 부활권을 미리 줄 수
  있다(기본값: 아무도 없음).
- 게임 중에도 언제든 생존자·탈락자 무관하게 특정 참가자에게 부활권을
  추가로 줄 수 있다("이 학생은 사정이 있었으니 하나 봐준다" 같은 상황 대응).
- "부활시키기"(탈락 취소)와 "부활권 부여"(다음 오답을 봐줄 안전장치)를
  **서로 독립된 별개의 버튼**으로 뒀다 — 탈락자를 되살리면서 부활권까지
  자동으로 얹지 않는다. 교사가 상황에 따라 둘을 따로 또는 같이 쓸 수 있게
  하기 위함("여러 상황을 생각해서 구현"이라는 요청 그대로).

## 설계 결정 — 그 외

- **라운드제, 턴 없음.** 매 라운드 하나의 문제를 생존자 전원에게 동시에
  낸다. `roundParticipantIds`(라운드 시작 시점의 생존자 목록, 고정)와
  `judgedThisRound`(이번 라운드에 판정된 참가자 집합)로 라운드 완료를
  추적 — 이 둘이 일치하면 자동으로 다음 라운드로 넘어간다.
- **판정은 기존 `Answer` 패턴을 그대로, 참가자마다 한 번씩 반복 호출한다.**
  체크리스트에서 참가자 행마다 "정답 처리"/"오답 처리"를 누르면 그 즉시
  `submitJudgment(participantId, judgedCorrect)`를 호출 — 별도의 "일괄 확정"
  액션 없이, 나중에 학생 개인 기기가 각자 다른 시점에 응답을 보내는 구조로도
  그대로 이어질 수 있게 했다.
- **객관식도 단답형과 동일하게 정답을 `AnswerConfirm`으로 가린다.** 지금까지
  객관식은 보기 버튼 클릭 방식이라 정답을 감출 필요가 없었지만, 골든벨은
  학생이 답을 직접 보이고 교사가 판정하는 방식이라 "정답: 보기 N번"도 화면에
  미리 노출되면 안 된다 — 정답 노출 방지 규칙을 객관식까지 확장한 첫 사례.
  `gradeAnswer`(choiceIndex 비교)를 쓸 수 없어서 정답 텍스트만 뽑는
  `answerText.ts`를 새로 만들었다.
- **탈락자는 화면에서 사라지지 않는다.** 체크리스트 하단에 탈락자 목록을
  계속 보여준다(CLAUDE.md의 "탈락자는 심판·응원단 역할" 취지).
- **시간제한 없음.** 생존자 1명 이하가 되거나 문제 큐가 소진되면 자동 종료.
  "다음 라운드로 강제 진행"(판정 안 된 참가자는 그대로 두고 넘어감) 버튼으로
  교사가 언제든 진행을 밀어붙일 수 있다.
- **점수 = 정답 라운드 수**(콤보·난이도 배율 없음) — "생존" 자체가 보상이라
  점수는 세션 기록 호환용 보조 지표로만 둔다.

## 검증 중 발견하고 고친 버그

브라우저 실제 플레이 중 발견: **게임 중간에 탈락자를 "부활시키기"로 되살려도
판정 버튼이 먹히지 않는 버그.** 원인은 두 가지가 겹쳐 있었다.

1. `REVIVE_MANUALLY`가 상태만 `alive`로 바꿀 뿐, 그 라운드의
   `roundParticipantIds`(라운드 시작 시점에 고정된 대상 목록)에는 추가하지
   않아 — `SUBMIT_ANSWER`가 "이번 라운드 대상이 아님"으로 판단해 판정을
   조용히 무시했다.
2. 첫 번째를 고친 뒤에도, 그 참가자는 탈락되기 직전에 이미
   `judgedThisRound`에 들어가 있어 체크리스트가 "판정됨"으로 표시해 버튼
   자체가 사라졌다.

`REVIVE_MANUALLY`가 `roundParticipantIds`에 추가하고 `judgedThisRound`에서는
제거하도록 고쳐서, 부활한 참가자가 그 라운드 안에서 다시 정상적으로 판정받을
수 있게 했다. 회귀 테스트로 이 시나리오를 별도로 검증했다.

## 검증 결과

- `npm run typecheck` 통과.
- 리듀서를 `tsx`로 직접 실행(임시 export 후 삭제): 초기 부활권 지급, 정답 시
  점수, 재판정 방지, 부활권 없이 오답 시 탈락, 탈락자 재판정 방지, 부활권
  있으면 오답이어도 생존(소비), 라운드 완료 시 생존자만 대상으로 자동 전환,
  생존자 1명 이하 시 종료, 강제 진행, `GRANT_REVIVAL`(생존/탈락 무관),
  `REVIVE_MANUALLY`, 수동 종료·점수 수정, 종료 후 액션 무시 — 총 22개
  케이스, 그리고 위 버그의 회귀 테스트 8개 케이스 확인.
- 브라우저로(fixture mock 디버그 하네스) 실제 플레이: 시작 시 특정 참가자에게만
  부활권이 부여되는지, 정답/오답/부활권 소비/탈락이 화면에 정확히 표시되는지,
  객관식 정답도 `AnswerConfirm`으로 가려지는지, 라운드 전원 판정 시 자동으로
  다음 문제로 전환되는지, 탈락자 목록이 유지되는지, "부활시키기"·"부활권 부여"가

  호출을 가로채 `gameMode: "goldenBell"`과 정확한 `finalScores`/`answers` 확인.
- 최종 `npm run dev`(Electron) 재부팅: 에러 없이 정상 기동 확인.
